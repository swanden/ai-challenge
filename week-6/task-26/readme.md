## TL;DR что сделано

- `local.go` — **клиент генерирующей локальной модели** поверх HTTP API Ollama (`/api/chat`,
  `/api/generate`, `/api/tags`). Чистый `net/http`, **без anthropic-sdk-go**, в том же стиле, что
  наш эмбеддер недели 5. Считает токены и скорость (ток/с) из ответа сервера.
- `local26.go` — самодокументируемое демо `-local26`: **три запроса разной сложности**, третий —
  **полностью локальный RAG** (поиск `nomic` + генерация локальной моделью), плюс интерактивный
  локальный чат `-local` (с опцией `-local-rag`).
- `main.go` — новые флаги `-local26 / -local / -local-model / -local-rag`; локальные режимы
  диспетчатся **первыми и не требуют** `ANTHROPIC_API_KEY`; `.env` больше не фаталит.
- **Ни одного облачного вызова** в этих режимах. Ровно сценарий из лекции: локальная LLM + локальный
  эмбеддинг = RAG, который не покидает машину.

## Ход мысли ПЕРЕД кодом (и главная развилка недели)

Задание дня 26 узкое: «запусти локалку, дёрни 3 раза». Но лекция ставит цель на **всю неделю** шире:
взять локальную модель и *применить к ней все джедайские техники* (MCP, RAG, task-state) и — в идеале —
сделать **тумблер облако↔локаль**, который гоняет один и тот же запрос в обе модели и сравнивает.

Отсюда развилка, которую надо назвать явно, **не** влетая в дорогую переделку:

> **Насколько глубоко втыкать локальную LLM уже сегодня?**
>
> - **A (узко, день 26):** отдельный самодостаточный клиент `LocalLLM` + демо на 3 запроса. Ничего в
    >   облачном пути агента не трогаем. Маленько, компилируется, честно закрывает задание.
> - **B (тумблер сейчас):** ввести общий интерфейс `Chat`/`Completer` и протянуть его через
    >   `agent.go`, `chat.go`, `rerank.go`, `cite.go`, `enforce.go`, `swarm.go` — все шесть зовут
    >   **конкретный** `anthropic.Client.Messages.New`. Это и есть лекционный тумблер, но это инвазивный
    >   рефактор шести файлов, завязанных на типы SDK (`TextBlockParam`, `tool_use`, `StopReason`,
    >   `ToolResultBlock`, `Usage`). Ошибиться в абстракции здесь = ровно та «дорогая переделка», которой
    >   мы избегаем.

**Выбрано A.** Причины: (1) день 26 буквально не требует тумблера — он требует «запущена и отвечает
на 3 запроса»; (2) тумблер и «интеграция во все флоу» — это дословно **день 27** («Интеграция локальной
LLM в приложение»); (3) правильный шов дешевле закладывать, когда он реально понадобится, чем гадать
сейчас. Поэтому `LocalLLM` сделан как **чистый самостоятельный клиент** — именно тот шов, который на
дне 27 обернётся интерфейсом. Подробнее — раздел [«Развилка дня 27»](#развилка-дня-27--что-дальше).

Второе решение: **где** живёт локальный движок. У нас уже есть локальный Ollama-код — эмбеддер в
`ragcore/embed.go`. Но `ragcore` — «единая точка правды **формата индекса**», а генерирующая LLM к
формату индекса отношения не имеет. Класть её туда — размывать пакет. Плюс каждый новый пакет — это
+1 к боли с переписыванием import-пути при копировании `task-(N)→task-(N+1)`. Поэтому `LocalLLM` —
файл `local.go` в `package main`, рядом с `agent.go`. Ноль новых import-путей на копирование.

## Два класса локальных моделей (важное различие из лекции и чата курса)

Курсовой чат в первый день недели 6 честно на этом споткнулся (Temi4: «а мы что делали с RAG?»),
и Гладков развёл:

> «Это разные темы моделей — **векторизующие и генерирующие**.»

| | Неделя 5 (RAG) | Неделя 6 (день 26) |
|---|---|---|
| Класс | **векторизующая** (эмбеддер) | **генерирующая** (LLM) |
| Модель | `nomic-embed-text` (768-dim) | `qwen2.5:7b`, `gemma`, `phi`, `llama`… |
| Эндпоинт Ollama | `/api/embeddings` | `/api/chat`, `/api/generate` |
| Что отдаёт | вектор (не отвечает на вопросы) | текст-ответ |
| Наш код | `ragcore.OllamaEmbedder` | `LocalLLM` (`local.go`) |

Транспорт и принцип — те же: локально, без ключа, данные не уходят («ollama serve» → «ollama pull»).
`local.go` намеренно повторяет стиль `ragcore/embed.go` (тот же `net/http`, та же диагностика «запущен
ли сервер, скачана ли модель»).

## Дизайн

```
                 ┌─────────────────────────────────────────┐
                 │            Ollama (localhost:11434)       │
                 │   генерирующая: qwen2.5 / gemma / phi …   │
                 │   векторизующая: nomic-embed-text         │
                 └───────────────▲───────────────▲───────────┘
     генерация (день 26)         │               │  эмбеддинг (неделя 5)
   /api/chat  /api/generate      │               │  /api/embeddings
                 ┌───────────────┴──┐         ┌──┴───────────────────┐
                 │  LocalLLM        │         │ ragcore.OllamaEmbedder│
                 │  (local.go)      │         │ (ragcore/embed.go)    │
                 └───────┬──────────┘         └──────────┬────────────┘
                         │                               │
                         │        ┌──────────────────────┘
                         ▼        ▼
                 ┌───────────────────────────┐
                 │ runLocal26 (local26.go)   │  3 запроса разной сложности
                 │  1) факт     /api/generate│
                 │  2) рассужд. /api/chat    │
                 │  3) локальный RAG:        │
                 │     поиск nomic + ответ   │
                 │     локальной моделью     │
                 └───────────────────────────┘
```

**Метрики.** `LocalStats` тащит из ответа Ollama `prompt_eval_count`, `eval_count`,
`eval_duration`, `load_duration` и меряет клиентский `wall`. `TokPerSec = eval_count /
eval_duration` — честная «толщина» модели: чем больше параметров, тем медленнее инференс (лекция).
`load_duration` велик на **первом** запросе (грузятся веса в память) — отсюда щедрый таймаут 5 минут.

**Заземление в запросе 3** повторяет принцип `chatAnswer` дня 25: system-промпт «отвечай ТОЛЬКО по
контексту, нет в базе — так и скажи». Поиск — bi-encoder `nomic` (локальный), **без** LLM-реранка:
реранк у нас — облачный судья (Haiku), а тут всё должно быть локальным. Перевести реранк на локальную
модель — задача дня 27 (см. ниже).

## Честные находки и пределы

- **Песочница не запускает Ollama** — живой прогон только на твоей M3 Max. Мой вклад: код +
  проверка контракта на фейковом сервере + типизация против реальных сигнатур. Контракт с недели 5
  прежний: ты гоняешь → присылаешь вывод → чиним по факту.
- **Формат в запросе 2 — индикатор слабости.** «Держи строгий формат `РЕЗУЛЬТАТ/ПОЧЕМУ`» — ровно то,
  на чём 7B-модели плывут (лишний текст до/после, markdown-обёртки). Если поедет — это честный
  результат «локалка слабее облака», а не баг. Можно ужать `-local-model` до инструктивной (`…-instruct`)
  или снизить температуру (сейчас 0.2).
- **В локальном RAG нет реранка.** Наш реранк — облачный судья (Haiku). В запросе 3 он выключен
  осознанно (иначе прогон перестанет быть локальным). Поэтому берём bi-encoder top-4 + порог 0.35.
  Перевод реранка на локальную модель — день 27.
- **`load_duration` на первом запросе** большой (веса грузятся в память). Второй и последующие —
  быстрее. Для видео можно сделать «прогрев» перед записью.
- **Русский корпус одноязычный** → query rewrite не нужен (как и на дне 25). В запросе 3 его нет.
- **Недетерминизм.** Локальные ответы плавают между прогонами — для видео берём удачный дубль
  (то же свойство, что у Haiku-судьи на неделе 5).

## FAQ

**Почему не anthropic-sdk-go для локали?** SDK говорит с Anthropic Messages API. У Ollama свой
HTTP-контракт. `LocalLLM` — чистый stdlib-клиент, самодостаточный. Это и есть шов под будущий тумблер.

**`/api/chat` vs `/api/generate`?** `chat` — роли (system+история+user), для диалога и заземления.
`generate` — одиночный prompt, как `ollama run <m> "<prompt>"`. Держим оба: запрос 1 идёт через
`generate` (показать «в лоб»), запросы 2–3 — через `chat`.

**Почему не стриминг?** `stream:false` — ждём весь ответ и парсим один JSON: детерминированно, без
склейки чанков. Для видео стриминг не нужен; добавить можно позже.

**LM Studio / llama.cpp вместо Ollama?** У LM Studio есть OpenAI-совместимый `/v1/chat/completions`.
Наш `do()` — тонкий; отдельный `openaiChat`-путь добавляется в `local.go` за ~30 строк. Пока —
нативный Ollama, как и эмбеддер.

**Ключ реально не нужен?** Да. `-local26/-local` диспетчатся до `anthropic.NewClient()`, `.env`
теперь не фаталит. Можно выдернуть интернет — запрос 3 (RAG) всё равно отработает локально.

## Развилка дня 27 — что дальше

День 27 = «интеграция локальной LLM в приложение» + лекционный **тумблер облако↔локаль**. Тогда и
настанет время варианта **B**. Предлагаемая форма шва (обсудим перед кодом):

```go
// общий контракт генерации, не зависящий от бэкенда
type Completer interface {
    Complete(ctx context.Context, system string, msgs []Msg, opt Opt) (Completion, error)
}
// две реализации: cloudCompleter (обёртка над anthropic.Client) и LocalLLM (уже готов).
// Agent.client anthropic.Client → Agent.llm Completer. Тумблер = какую реализацию положили.
```

Больной вопрос — **tool-use**: облачный путь агента крутит `StopReason==tool_use` и `ToolResultBlock`
(SDK-специфика). Ollama tool-calling умеет, но формат другой. Для дня 27 разумно: тумблер покрывает
**RAG-чат и task-state** (там tool-use не в ядре), а MCP-цикл пока остаётся облачным — и это честно
отметить. Прежде чем резать `agent.go`, хочу свериться с тобой по границе тумблера.
