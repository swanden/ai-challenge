# День 3. Разные способы рассуждения

## Задание

🔥 **День 3. Разные способы рассуждения**

Возьмите одну задачу (логическую, алгоритмическую или аналитическую)

Решите её через API четырьмя способами:
- 👉 получите прямой ответ без дополнительных инструкций
- 👉 добавьте в промпт инструкцию: «решай пошагово»
- 👉 попросите модель сначала составить промпт для решения задачи, а затем используйте его
- 👉 создайте в промпте группу экспертов (например: аналитик, инженер, критик) и получите решение от каждого

Сравните:
- 👉 отличаются ли ответы
- 👉 какой способ дал наиболее точный результат

**Результат:** несколько решений одной задачи и их сравнение

**Формат:** видео + код

---

Одна задача решается через API **четырьмя способами**, после чего ответы сравниваются. Цель — увидеть, как меняется качество решения в зависимости от того, как сформулирован промпт.

## Задача-пример

> Бита и мяч вместе стоят 1.10$. Бита стоит на 1.00$ дороже мяча. Сколько стоит мяч?

Правильный ответ — **0.05$** (мяч 0.05$, бита 1.05$, разница ровно 1.00$). Интуитивный ответ «10 центов» неверен — поэтому на этой задаче хорошо видна разница между способами.

> Температура во всех вызовах зафиксирована (`0.0`), чтобы расхождения объяснялись способом рассуждения, а не случайностью сэмплинга.

## Способ 1. Прямой ответ

Промпт: задача отправляется как есть, без инструкций.

**Что даёт:** базовая точка отсчёта. Модель отвечает «навскидку», коротко. На задачах-ловушках чаще промахивается, потому что не разворачивает рассуждение и идёт за первым правдоподобным ответом.

## Способ 2. «Решай пошагово»

Промпт: к задаче добавляется инструкция расписать каждый шаг рассуждения перед итоговым ответом.

**Что даёт:** chain-of-thought. Модель сначала формализует условие (`мяч = x`, `бита = x + 1`, `2x + 1 = 1.10`), а потом считает. Это резко повышает точность на логических и арифметических задачах — ловушка «10 центов» обычно исчезает.

## Способ 3. Модель сама пишет промпт

Два вызова: сначала модель в роли инженера промптов составляет промпт под задачу, затем по этому промпту получаем решение.

**Что даёт:** meta-prompting. Модель сама добавляет то, что человек мог упустить: просьбу проверить ответ, учесть крайние случаи, формат вывода. Качество часто близко к «пошагово», но решение бывает полнее и аккуратнее структурировано. Минус — лишний вызов и зависимость от качества сгенерированного промпта.

## Способ 4. Группа экспертов

Системный промпт задаёт три роли — **аналитик**, **инженер**, **критик** — и каждый решает задачу **отдельным вызовом**. Получаем решение от каждого.

**Что даёт:** взгляд с разных сторон. Аналитик формализует, инженер считает по шагам, критик перепроверяет и ловит ловушки. Сравнивая три решения, легко заметить ошибку, если она есть. Самый «дорогой» способ по числу вызовов, но самый надёжный для проверки ответа.

## Сравнение

| Способ | Промпт | Что добавляет | Точность на задаче-ловушке |
|---|---|---|---|
| 1. Прямой | задача как есть | ничего | низкая / нестабильная |
| 2. Пошагово | + «рассуждай по шагам» | развёрнутое рассуждение | высокая |
| 3. Само-промпт | модель пишет промпт | самопроверка, структура | высокая |
| 4. Эксперты | роли + отдельные вызовы | разные точки зрения, перепроверка | высокая, с контролем |

**Вывод:** простое добавление инструкции «рассуждай пошагово» уже сильно поднимает точность по сравнению с прямым ответом. Само-промпт и группа экспертов дают сопоставимую точность, но ценой дополнительных вызовов; их главное преимущество — полнота решения и возможность перепроверки.
