## Параметры контроля и зачем они нужны

Контролировать ответ можно на двух уровнях: **мягком** (просьба в промпте, модель старается выполнить) и **жёстком** (параметр API, ограничение применяется принудительно).

### 1. System (системный промпт) — формат ответа

Задаёт правила, по которым модель строит ответ: стиль, структуру, длину словами, формат вывода. В коде:

> «Отвечай кратко, не более 2 предложений. Формат: обычный текст без списков. В самом конце ответа поставь маркер `###END###`.»

Это **мягкий** контроль: модель следует инструкции, но строгой гарантии нет — поэтому его дополняют жёсткими параметрами.

### 2. MaxTokens — ограничение длины

Жёсткий потолок на количество сгенерированных токенов. Без ограничений — `1024`, с ограничениями — `100`. Это **физический** лимит: даже если модель захочет продолжить, генерация оборвётся. Минус — если поставить слишком мало, ответ может обрезаться на полуслове, поэтому длину дублируют и в промпте («не более 2 предложений»).

### 3. StopSequences — условие завершения

Список строк, при встрече которых генерация немедленно останавливается. В коде это `###END###`. Модель по инструкции ставит маркер в конце ответа, а `StopSequences` гарантированно завершает на нём генерацию.

> Важно: сама стоп-последовательность **не попадает** в текст ответа — API обрезает её. Поэтому `###END###` в выводе не виден, ответ выглядит чисто.

**Итог:** формат задаётся системным промптом (мягко), длина — `MaxTokens` (жёстко) + словами в промпте (мягко), завершение — `StopSequences` (жёстко) + маркером в промпте (мягко). Мягкое и жёсткое дополняют друг друга.

## Пример запуска

**Запрос:** «Расскажи про язык программирования Go.»

### Без ограничений (`use constraints? n`)

```
Go (или Golang) — компилируемый язык программирования, созданный в Google
в 2009 году Робертом Гризмером, Робом Пайком и Кеном Томпсоном. Он сочетает
простоту синтаксиса с высокой производительностью и был разработан для решения
проблем масштабной разработки.

Ключевые особенности:
- Статическая типизация и быстрая компиляция
- Встроенная поддержка конкурентности (горутины и каналы)
- Сборщик мусора
- Богатая стандартная библиотека

Go широко используется для бэкенда, облачных сервисов, CLI-утилит и
инфраструктурных инструментов (Docker, Kubernetes написаны на Go)...
```

### С ограничениями (`use constraints? y`)

```
Go — компилируемый язык от Google со статической типизацией, простым
синтаксисом и встроенной поддержкой конкурентности через горутины. Его часто
выбирают для бэкенда, облачных сервисов и инфраструктурных инструментов.
```

### Чем отличается

| | Без ограничений | С ограничениями |
|---|---|---|
| Длина | несколько абзацев | 2 предложения |
| Формат | заголовки, списки, markdown | сплошной текст без списков |
| Завершение | заканчивается, когда «выговорится», или упирается в `MaxTokens=1024` | гарантированно завершается на маркере `###END###` |
| Предсказуемость | низкая | высокая — ответ стабильно влезает в заданные рамки |

## Вывод

Один и тот же запрос можно получить с совершенно разным уровнем контроля. Системный промпт направляет формат, но не гарантирует его; жёсткие параметры (`MaxTokens`, `StopSequences`) дают гарантию длины и завершения. Надёжнее всего комбинировать оба уровня: описать формат словами **и** подкрепить параметрами API. Контролируемый ответ предсказуем, дешевле по токенам и проще для дальнейшей обработки — это важно, когда ответ модели идёт не человеку, а в код (парсинг, интеграции, UI).
