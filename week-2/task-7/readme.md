# 🔥 День 7. Сохранение контекста

## Задание

Добавьте агенту сохранение контекста:

- 👉 храните историю диалога (messages) в JSON или SQLite
- 👉 при перезапуске агента загружайте историю обратно
- 👉 продолжайте диалог так, как будто агент не выключался

## Проверьте на практике

- 👉 начните диалог
- 👉 перезапустите приложение
- 👉 продолжите диалог и убедитесь, что агент помнит прошлые сообщения

## Результат

Агент, который сохраняет и восстанавливает контекст между запусками.

## Формат

Видео + Код

## Реализация

Контекст персистится в JSON-файл. Хранилище спрятано за интерфейсом `Store`,
поэтому реализацию можно подменить на SQLite, не трогая агента.

- `store.go` — интерфейс `Store` (`Load`/`Save`) и реализация `JSONStore`.
  На диске лежит формат, независимый от типов SDK:
  `[{"role": "...", "content": "..."}]`. Запись атомарная (temp + rename).
- `agent.go` — `NewAgent` грузит историю при старте; после каждого хода
  вызывает `store.Save`. История (`[]storedMessage`) — источник правды,
  в запрос SDK конвертируется на лету.
- `main.go` — собирает цепочку `client → store → agent`, при старте сообщает,
  сколько сообщений восстановлено.

### Запуск

```bash
# .env должен содержать ANTHROPIC_API_KEY
go run .
```

> Запускать `go run .`, а не `go run main.go` — иначе пакет не увидит
> остальные `.go`-файлы.

История диалога окажется в `history.json` рядом с бинарником — файл
человекочитаемый, можно открыть и посмотреть.

### Известное ограничение

История растёт неограниченно, и каждый запрос отправляет её целиком — это
расход токенов, стоимости и упор в контекстное окно. Для учебной задачи
нормально; обрезка/суммаризация старых сообщений — тема следующих дней.
