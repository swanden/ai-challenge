# 🔥 День 8. Работа с токенами

## Задание

Добавьте в код агента подсчёт токенов: для текущего запроса · для всей истории · для ответа модели.
Сравните короткий / длинный / превышающий лимит диалог. Покажите, как растёт стоимость
и что ломается при переполнении.

## Результат

Код, который считает токены и показывает, как они влияют на поведение агента.
**Программа сама прогоняет сценарии, печатает диалоги и делает выводы из реальных чисел.**

Видео + Код

## Два режима

### 1. Отчёт — программа всё считает сама

```bash
go run . -report
```

Прогоняет три сценария на чистых агентах (история в памяти, `history.json` не трогается):
для каждого печатает **транскрипт диалога** (ответы модели обрезаются до одной строки),
**таблицу токенов** и в конце — **выводы, посчитанные из чисел**.

Числа берутся из API:

- **текущее сообщение** — `Messages.CountTokens` на одном сообщении (бесплатный endpoint);
- **история / весь запрос** — `msg.Usage.InputTokens`;
- **ответ модели** — `msg.Usage.OutputTokens`.

### 2. Интерактивный чат (дни 6–7 + учёт токенов)

```bash
go run .
```

Сохраняет контекст в `history.json`, после каждого хода печатает разбивку токенов
и накопленную стоимость.

## Колонки таблицы

```
ход  msg  input(ctx)  output  Σinput  Σoutput  Σcost
```

- **ход** — номер хода в диалоге. Один ход = одна реплика пользователя + один
  ответ модели.
- **msg** — токены *только текущего сообщения пользователя* (этот вопрос сам по
  себе), измерены `CountTokens` на одном сообщении.
- **input(ctx)** — токены *всего запроса*, ушедшего в модель на этом ходу:
  вся история диалога + текущее сообщение (`Usage.InputTokens`). Растёт от хода
  к ходу, потому что контекст накапливается.
- **output** — токены *ответа модели* на этом ходу (`Usage.OutputTokens`).
- **Σinput** — накопленная сумма `input(ctx)` по всем ходам сессии. Это не то же,
  что последний `input(ctx)`: за input платят *каждый* ход заново, ведь вся история
  пересылается снова. Тарифицируется по $5 / 1M.
- **Σoutput** — накопленная сумма `output` по всем ходам сессии. Тарифицируется
  по $25 / 1M.
- **Σcost** — накопленная стоимость сессии: `Σinput × $5/1M + Σoutput × $25/1M`.

> Ключевой момент: `input(ctx)` — это нагрузка одного хода, а `Σinput` — суммарная
> оплата за всё. Так как каждый ход тащит всю историю, `Σinput` растёт быстрее,
> чем линейно — отсюда и рост `Σcost`.

## Выводы по задаче

**Как растёт стоимость/токены по мере диалога.** В модель каждый ход уходит *вся*
история, поэтому `input(ctx)` растёт от хода к ходу, а вместе с ним — стоимость хода,
даже если сам вопрос короткий (в примере контекст одного хода вырос с 21 до 505 токенов,
×24). Короткий диалог стоит копейки; длинный — кратно дороже не из-за числа ходов,
а из-за того, что каждый ход тащит за собой накопленный контекст.

**Output весит больше input.** Тариф на выход в 5 раз выше входа ($25 против $5),
поэтому в счёте ответы модели занимают непропорционально большую долю. Практический
вывод: чтобы снизить стоимость, в первую очередь ограничивают длину ответов
(`MaxTokens`, просьба отвечать кратко), а уже потом ужимают промпты.

**Что ломается при переполнении.** Контекстное окно Opus 4.8 — **1M токенов**
(макс. ответ — 128k). Когда запрос (история + новое сообщение) превышает лимит,
API отклоняет вызов целиком. В коде стоит проактивная защита: перед отправкой запрос
считается через `CountTokens`, и при превышении лимита ход не уходит в API, а возвращается
`ContextOverflowError`. В примере при жёстком лимите 500 токенов диалог отработал 4 хода
и сломался на 5-м (548 токенов). Без обрезки или суммаризации истории диалог в этой точке
просто перестаёт работать — это и есть «переполнение».

## Как устроено

- `usage.go` — `TokenStats`, тариф Opus 4.8, `costUSD`, лимит контекста.
- `agent.go` — `Ask` возвращает `Reply{Text, Tokens}`; считает токены, копит итоги;
  опции `WithContextLimit` / `WithMaxTokens`; типизированная `ContextOverflowError`.
- `report.go` — сценарии, прогон, транскрипт с обрезкой (`oneLine`), таблицы и выводы.
- `store.go` — `JSONStore` (диск, день 7) + `MemoryStore` (для отчёта).
- `main.go` — флаг `-report` либо интерактивный чат.
