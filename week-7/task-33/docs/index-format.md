# Формат индекса RAG (схема данных)

Пакет `ragcore` — единая точка правды формата индекса. Его импортируют оба конца:
продьюсер (`ragindex/` — собирает индекс) и консьюмер (агент — читает и ищет).
Структуры не дублируются, поэтому индекс не может «разъехаться» между ними.

## Chunk — единица индексации

```go
type Chunk struct {
    ID      string    `json:"chunk_id"`         // уникальный id, напр. "docs/architecture.md#003-completer"
    Source  string    `json:"source"`           // относительный путь файла
    File    string    `json:"file"`             // имя файла
    Section string    `json:"section"`          // раздел: заголовок .md / имя декларации .go / "part N"
    Text    string    `json:"text"`
    Tokens  int       `json:"tokens"`           // приближённый размер в словах
    Vector  []float32 `json:"vector,omitempty"` // L2-нормированный эмбеддинг (пусто при -dry-run)
}
```

Метаданные (`source`, `file`, `section`, `chunk_id`) есть на **каждом** чанке — именно они
позволяют ассистенту не просто ответить, а сослаться на источник и процитировать его.

## Index — файл индекса

```go
type Index struct {
    Model     string  `json:"model"`      // модель эмбеддингов, напр. "nomic-embed-text"
    Dim       int     `json:"dim"`        // размерность вектора (для nomic-embed-text — 768)
    Strategy  string  `json:"strategy"`   // "fixed-size" | "structural"
    ChunkSize int     `json:"chunk_size,omitempty"` // только для fixed-size
    Overlap   int     `json:"overlap,omitempty"`    // только для fixed-size
    Chunks    []Chunk `json:"chunks"`
}
```

Хранится как JSON. Индекс агента задаётся флагом (`-index`, `-index-ru`, `-index-docs`).

**Инвариант:** модель эмбеддингов агента (`-embed-model`) обязана совпадать с `Model`
индекса. Разные эмбеддеры дают несравнимые векторные пространства — поиск молча выродится
в шум, без единой ошибки.

## Стратегии chunking

Индексатор всегда собирает **обе** стратегии и пишет `comparison.md` со сравнением.

### fixed-size

Режет по N слов с перекрытием (`-chunk-size`, по умолчанию 500 слов; `-overlap`, 50 слов).
Просто и предсказуемо, но рвёт мысль на середине предложения.

### structural (используется по умолчанию)

Режет по структуре файла:

| Тип файла | Как режется | Что попадает в `Section` |
|---|---|---|
| `.go` | по верхнеуровневым декларациям через `go/parser` (AST): «шапка» (package + import), затем по чанку на каждую `func`/`type`/`const`/`var` | имя декларации |
| `.md` | по заголовкам любого уровня; код-блоки в ```-фенсах не разрываются | текст заголовка |
| прочее | по абзацам (пустая строка) | `part N` |

**Потолок размера markdown-чанка: 1500 символов** (`mdMaxRunes`).

Зачем потолок — это найденный баг. Эмбеддер молча усекает вход до `-max-embed-chars`
(по умолчанию 1800 символов) и считает усечения в `emb.Truncated`. Раньше markdown-секция
не имела ограничения по размеру, поэтому длинная секция попадала в вектор только своей
первой половиной, хотя целиком лежала в `Text` чанка. Результат: чанк искался по обрезку —
тихая потеря recall ровно на самых содержательных разделах. Теперь секция пакуется в
под-чанки по границам абзацев и целых код-блоков, а строка заголовка дублируется в каждый
под-чанк (вместо word-overlap: мысль не рвётся, а эмбеддеру важно знать, что это за раздел).

## Эмбеддинги

`OllamaEmbedder` (`ragcore/embed.go`), модель по умолчанию `nomic-embed-text`, dim 768,
векторы L2-нормированы (поэтому косинус = скалярное произведение).

**Асимметричные префиксы.** `nomic-embed-text` требует разных префиксов для документа и
для запроса: `EmbedDocument` и `EmbedQuery` — разные методы, а не один `Embed`. Без этого
качество поиска заметно падает; это тоже найдено на реальных прогонах.

## Поиск

`Index.Search(ctx, embedder, query, k)` — косинусная близость, top-k.

Поверх него в агенте — двухстадийный конвейер `retrieveAdvanced` (`rerank.go`):
query rewrite → bi-encoder top-N → `FilterThreshold` → `MMR` (диверсификация, λ по
умолчанию 0.7) → LLM-реранк → top-K. Трасса каждого шага возвращается в `RetrievalTrace`.

## Корпуса

| Индекс | Что внутри | Чем собран |
|---|---|---|
| `ragindex/` | исходники агента + README (корпус дня 21) | `go run ./ragindex` |
| `ragindex-ru/` | 12 лекций по ML (ВШЭ), русский корпус | `go run ./ragindex -docs corpus-ru` |
| `ragindex-docs/` | **документация проекта: readme.md + docs/ + код агента** | `go run ./ragindex -out ragindex-docs -ext .md,.go` |

`ragindex-docs` — корпус ассистента разработчика (`/help`). Он собирается по каталогу
самого проекта; лекции, артефакты индексов и рантайм-состояние (`memory/`, `notes/`,
`reports/`) из него исключены — см. `defaultSkipDirs`.
