# Ограничение частоты внешнего API (429)

## Симптом

В логе — ответы `429 Too Many Requests` от внешнего сервиса, иногда с заголовком
`Retry-After`. Часть запросов пользователей падает, в трейсах видно, что ошибка приходит
именно от внешнего вызова, а не от собственной базы. Проблема усиливается в часы пиковой
нагрузки.

## Причина

Сервис шлёт во внешний API больше запросов, чем разрешает его лимит. Обычно это следствие
отсутствия ограничения на своей стороне: каждый пользовательский запрос порождает вызов
внешнего API один в один, без кэширования и без сглаживания пиков. Иногда лимит внешнего
API понизили, а на нашей стороне это не учли. Ретраи без задержки только ухудшают ситуацию,
добавляя нагрузки.

## Как чинить

Уважать заголовок `Retry-After` и делать ретраи с экспоненциальной задержкой, а не сразу.
Поставить на своей стороне ограничитель частоты (rate limiter), чтобы не превышать лимит
внешнего API. Кэшировать ответы, которые не меняются часто, чтобы не дёргать API на каждый
запрос. Где возможно — объединять несколько запросов в один batch. Для некритичных вызовов
использовать очередь и обрабатывать её с постоянной скоростью, а не всплесками.

## Как отличить от похожего

Отличать от таймаута: 429 — это явный ответ сервера «слишком часто», внешний сервис жив и
отвечает. Таймаут — это отсутствие ответа вообще.
