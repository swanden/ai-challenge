# MCP-серверы и тулы (API-описание)

Агент подключается к трём MCP-серверам. Каждый — отдельный процесс, транспорт stdio,
запускается агентом как сабпроцесс (`go run ./<server>`).

Клиент — `mcptools.go`. Он делает три вещи:

1. **агрегирует** тулы всех серверов в один список для модели;
2. **маршрутизирует** вызов по имени тула к серверу-владельцу (`route[name] → session`);
3. **лениво отдаёт схемы** (флаг `-lazy`, по умолчанию включён): модель сначала видит
   только каталог серверов и мета-тул `load_tools`, а схемы конкретного сервера
   подмешиваются только после того, как модель его запросила. Это экономит контекст.

Прямой вызов тула из кода — `MCPTools.Call(ctx, name, args)`. Он идёт мимо модели и не
тратит токены; так работают `/track`, `/summary` и пре-фетч git-контекста в `/help`.

## Сервер `git` (`gitserver/`) — контекст проекта

**Только чтение.** Белый список подкоманд: `rev-parse`, `status`, `ls-files`, `diff`, `log`.
Запись (`add`, `commit`, `push`, `checkout`, `reset`, `config`) невозможна по построению —
такого кода в сервере нет. Аргументы из JSON проверяются: ведущий дефис запрещён (иначе
путь притворился бы флагом git), выход за пределы репозитория запрещён, набор символов
ограничен. Вывод усекается до 8000 символов, таймаут 20 секунд.

| Тул | Параметры | Возвращает |
|---|---|---|
| `git_branch` | нет | текущая ветка, короткий SHA HEAD, upstream, число незакоммиченных файлов |
| `git_files` | `path` (префикс пути), `limit` (по умолчанию 200) | файлы **рабочего дерева**: отслеживаемые (`--cached`) + новые (`--others`, с учётом `.gitignore`). Счётчики — в шапке ответа |
| `git_diff` | `ref` (ревизия или диапазон), `path`, `stat` (bool) | diff; по умолчанию — рабочее дерево против HEAD |
| `git_log` | `limit` (по умолчанию 10, максимум 50), `path` | последние коммиты: SHA, дата, автор, заголовок |

Корень репозитория определяется через `git rev-parse --show-toplevel`; переопределяется
переменной окружения `GIT_REPO`.

**Почему `git_files` смотрит рабочее дерево, а не только индекс.** Простой `git ls-files`
показывает только отслеживаемые файлы. На свежем, ещё не закоммиченном каталоге ассистент
увидел бы почти пустой проект. Но файл, который разработчик только что создал, — как раз самый
интересный для вопроса «что у меня в проекте». Поэтому берутся обе категории.

## Сервер `weather` (`weatherserver/`) — погода и фоновое слежение

| Тул | Что делает |
|---|---|
| `geocode` | город → координаты |
| `weather_current` | текущая погода по локации |
| `weather_collect` | разовый сбор замера |
| `track_location` | поставить город на фоновый сбор с заданным интервалом |
| `untrack_location` | снять город с отслеживания |
| `list_tracked` | что сейчас отслеживается |
| `weather_summary` | агрегированная сводка по накопленным замерам |
| `make_report` | собрать отчёт (композиция пайплайна на стороне сервера) |

## Сервер `notes` (`notesserver/`) — файловое хранилище

| Тул | Что делает |
|---|---|
| `save_to_file` | сохранить текст в файл в каталоге `notes/` |
| `read_file` | прочитать сохранённый файл |
| `list_files` | список файлов |
| `delete_file` | удалить файл |

Имена файлов очищаются от путей (`safeName`) — защита от path traversal.

## Об опасных операциях

Лекция недели 7 требует отдельного гейта на опасные операции (удаление файлов, `git push`,
правка конфигов) с подтверждением у человека.

В агенте эта проблема решена **архитектурно, а не процедурно**: git-сервер физически не
умеет писать. Гейт не нужен, потому что гейтить нечего. Единственный сервер, который
пишет на диск, — `notes`, и он ограничен собственным каталогом.

Как только появится операция, которая меняет мир снаружи (например, публикация комментария
в PR), человеко-в-цикле понадобится по-настоящему — и это будет отдельная работа, а не
галочка.
