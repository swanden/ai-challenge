# Мой рабочий процесс (как я веду разработку с ИИ)

Личный воркфлоу автора репозитория — как задания недельного челленджа делаются
на практике. Не часть конкретной задачи; общий процесс.

## Пошагово

1. **Память проекта = `CLAUDE.md`.** В проекте заведён файл памяти проекта (`CLAUDE.md`),
за которым я слежу, чтобы ассистент его регулярно обновлял. Иначе задалбывает
перетаскивать контекст между сессиями вручную.

2. **Новое задание → новая сессия + контекст.** Когда прилетает задача: создаю новую
сессию, кидаю туда summary недельного видео (те `.md`, что присылают), затем текст
задачи; если по ней уже есть обсуждение в чате курса — докидываю и его. Включаю
plan mode и жду план.

3. **Ревью плана.** Внимательно прохожусь по плану (насколько сил хватает), делаю
замечания, ассистент правит план — иногда за несколько итераций.

4. **Запуск.** Дальше запускаю — в целом задача выходит часа за два.

5. **Сценарии для видео.** Когда готово, прошу придумать сценарии для записи видео.

> Нюансы: пункт 5 обычно полностью переделываю — рекомендации по сценарию слабые. План
> иногда сильно правлю архитектурно. Между днями уже накопилось много правок.

## Заметки по стабилизации процесса (из обсуждений в чате)

Приёмы, которые участники отмечали как полезные (на будущее, опционально):
- разбивать план на **атомарные подзадачи** в отдельные файлы и решать их по одной с
подтверждением — стабилизирует процесс;
- в план сразу закладывать, чтобы на каждом этапе всё **компилировалось, тестировалось и
коммитилось** (проще ревьюить по коммитам);
- держать **юнит-тесты** и прогонять их на каждой итерации — ловит повторяющиеся косяки;
- периодически просить ассистента **удалять накопившийся мусорный код** и разносить на
модули.
